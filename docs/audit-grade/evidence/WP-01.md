## Arquitectura resultante

```text
CI build-images (una vez por servicio y SHA)
  -> Python + invariantes
  -> workflow contracts/actionlint
  -> Dataform compile
  -> dashboard build
  -> Terraform fmt/init/validate
  -> dependency review
  -> CI gate
  -> workflow_run exitoso de push a main para el SHA exacto
  -> GitHub environment production (aprobacion manual pendiente de configurar)
  -> publicar el artefacto verificado y resolver digest
  -> revision Cloud Run sin trafico
  -> smoke read-only
  -> promover trafico o rollback
```

`.github/workflows/ci.yml` se ejecuta en `pull_request` hacia `main`, `push` a `main` y `workflow_dispatch`. Ningun job de CI tiene permisos `write` ni acceso a secretos de GCP.

`.github/workflows/deploy.yml` solo acepta `workflow_run` de `CI`, exige conclusion `success`, evento original `push`, rama `main`, repositorio de origen identico y el SHA actual de `main`. No acepta `pull_request`, `push`, `master` ni `workflow_dispatch`. La autenticacion GCP ocurre despues del gate `environment: production`.

`deploy-dashboard.yml` tambien elimino `master`, push directo y dispatch manual. Su ejecucion programada o por `workflow_run` resuelve un SHA de `main` con CI exitoso antes de compilar y publicar GitHub Pages.

## Build once y digest

CI construye ocho imagenes a partir del inventario versionado `scripts/ci/cloud_run_services.json`. Cada artefacto incluye:

- contexto de build;
- SHA Git exacto;
- image ID local;
- archivo `image.tar.gz`;
- checksum SHA-256.

Deploy descarga exclusivamente los artefactos del run CI que lo disparo, verifica inventario, checksum y SHA antes y despues del approval, comprueba que el SHA aun sea el `main` remoto actual, publica una vez y obtiene una referencia inmutable `@sha256:`. Cloud Run recibe el digest, nunca el tag mutable. La logica esta probada; la promocion live permanece sin ejecutar, por lo que CI-05 es `PARTIAL`.

## Invariantes de seguridad

`scripts/ci/verify_repo_invariants.py` falla cerrado ante:

- `PAPER_CHAMPION`, modos live o ejecucion no Paper;
- `production_change_allowed=true`;
- Strategy Brain fuera de `BACKTEST_ONLY` o schedulers no pausados en el baseline;
- reactivacion o mutacion de schedulers desde deploy;
- deploy desde `master`, PR, push directo, dispatch o sin CI exitoso;
- secretos de alta confianza en archivos versionables;
- eliminacion del lock legacy;
- `LEGACY_PRE_AUDIT_GRADE` elegible para promocion.

La ejecucion sobre el repositorio real produjo `REPO_INVARIANTS_VALID`. Las pruebas negativas producen exit code distinto de cero para cada estado peligroso.

## Smoke y rollback

`scripts/ci/smoke_test_services.py` solo ejecuta `gcloud run revisions describe`, con timeout y salida JSON estructurada. Exige revision `Ready=True`, generacion observada e imagen exactamente igual al digest aprobado. No llama endpoints funcionales, no crea ordenes, no escribe tablas, no ejecuta estrategias y no envia alertas.

Cada revision se crea con cero trafico. Ante un error, el workflow conserva la revision previa y, si ya promovio algun servicio, restaura trafico en orden inverso. El algoritmo y los contratos tienen pruebas unitarias. No se hizo un drill live, por lo que OP-05 es `PARTIAL`. El procedimiento operativo esta en [WP-01_CI_CD_GOVERNANCE.md](../runbooks/WP-01_CI_CD_GOVERNANCE.md).

- default branch, ruleset `main` y environment `production` no estan configurados;
- workflow Cloud Run permanece intencionalmente deshabilitado;
- rollback no fue probado contra Cloud Run live;
- CI usa `GCP_SA_KEY` solo despues del approval; WIF corresponde a WP-10;
- Artifact Registry debe existir y conservar permisos adecuados; deploy falla cerrado si no existe;
- vulnerabilidades heredadas de Dataform/Evidence siguen abiertas;
- smoke valida readiness e identidad del contenedor, no invoca endpoints de negocio para evitar efectos laterales.
