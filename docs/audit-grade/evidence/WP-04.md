- las revisiones raw son append-only y content-addressed;
- provider, interval, timezone, exchange, source version y run ID son explícitos;
- una vela diaria nunca se suma simultáneamente con sus barras intradía;
- intradía incompleto cae a daily con reason code;
- ejecución usa raw OHLC y retornos usan adjusted close;
- BTC/ETH se construyen únicamente desde cuatro barras horarias completas por bucket 4h UTC;
- XNYS contempla DST, feriados y early closes;
- las fechas daily se clasifican por la fecha calendario del proveedor antes de UTC;
- Yahoo `CLP=X` queda exclusivamente `DIAGNOSTIC_ONLY` tras 44 rechazos, 43 materiales;

- Yahoo y Stooq se reconcilian con estados explícitos;
- mismatch material y fuente stale bloquean calidad;
- el bridge feature-flagged es una tabla shadow separada; la acción operacional permanece intacta;
- dual-run y evidencia nunca son promotion eligible;

## Limitaciones explícitas

1. Yahoo no expone un timestamp histórico de publicación verificable para todas
   las corporate actions. Esas filas se retienen como
   `UNVERIFIED_AVAILABLE_AT`, `backtest_eligible=false`; no se fabrica historia.
2. Adjusted close del proveedor se conserva como serie de retorno. La tabla de
   acciones aporta lineage y soporte prospective, pero no convierte un backfill
   sin publication timestamp en PIT elegible.
3. Stooq se usa como segunda fuente diaria configurable. No cubre cripto ni FX
   en este WP.
4. BDE no expone un ledger completo de revisiones históricas. Solo pueden
   preservarse las revisiones observadas por FirstLayer desde su ingesta.
5. Ningún resultado es promocionable hasta completar schema graph, backfill,
   materialización, audit y revisión independiente.
