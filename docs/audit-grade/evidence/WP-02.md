## Resultado implementado

WP-02 introduce una capa auditable que separa la identidad del experimento de
las tablas operativas legacy:

```text
contratos YAML versionados
  -> hashes canónicos de contrato y schema
  -> data_snapshot_id publicado e inmutable
  -> experiment_id UUID antes de candidatos
  -> run_id content-addressed por intento
  -> candidate_id SHA-256(experiment, run, generation, parent, config)
  -> artefactos y decisiones inmutables
  -> publicación solo tras cobertura completa
  -> replay read-only por manifest
```

El wrapper `main_wp02.py` instala el registry alrededor del Strategy Brain
existente. El motor legacy continúa siendo la implementación de señales; el
adapter controla identidad, snapshot, candidatos, estados y evidencia sin darle
autoridad productiva.

## Contratos machine-readable

Se versionan doce contratos:

- cinco tablas nuevas del audit registry;
- tres tablas legacy del Strategy Brain extendidas;
- precios, estados financieros, earnings y ejecuciones Paper actuales.

Los inputs legacy con defectos temporales conocidos se clasifican
explícitamente como `NOT_BACKTEST_ELIGIBLE`; WP-02 no convierte datos antiguos
en evidencia point-in-time.

Manifiestos canónicos:

```text
data_contract_version = audit-contracts-v1
contract_set_hash = 94613f94d09fe13f15682d2678a11d6f98faf4b88234c52dcf59d76d1ebf8a49
schema_snapshot_hash = f7dac8b63c1ead7e6294496417ed94ba87f411cd8293d0a09aa90a400a0e8b73
```

`validate_data_contracts.py` verifica estructura, claves, semántica temporal,
implementación declarada y drift de ambos manifests. El validador separado de
schema observado falla ante tablas ausentes o cambios de tipo/modo.

## Data snapshots

`packages/common/data_snapshots.py` y `research/snapshot_manifest.py` crean un
registro determinístico, no mutante, con:

- versión y hash del contrato;
- hash del schema esperado;
- cutoff UTC;
- manifest y checksum de las fuentes;
- quality gate;
- estado y timestamps;
- `production_change_allowed=false`.

Solo `quality_gate_status=PASS` permite `PUBLISHED`. Un snapshot publicado queda
`immutable=true`; una corrida del Strategy Brain rechaza cualquier snapshot
inexistente, mutable, no publicado, con calidad distinta de PASS o con hashes
incompatibles.

## Experiment registry

Las tablas nuevas son:

```text
audit_data_snapshots
audit_experiment_runs
audit_experiment_candidates
audit_experiment_artifacts
audit_experiment_decisions
```

Las claves siempre incluyen el contexto completo. `candidate_id` nunca se usa
como sustituto de `experiment_id/run_id`.

Los candidatos operativos se insertan inicialmente como `REGISTRY_PENDING`.
Solo después de persistir el experimento y el conjunto completo en el registro
se activan como `BACKTEST_ONLY`. La vista de variantes además exige la presencia
del run y del candidato auditados. Un fallo intermedio deja el experimento como
`FAILED` y no publica el conjunto parcial.

Estados del experimento:

```text
CREATED -> CANDIDATES_READY -> RUNNING -> COMPLETED
        -> REJECTED | FAILED | CANCELLED
```

`production_change_allowed` permanece falso en runs, candidatos y decisiones.
El scheduler del Strategy Brain continúa pausado.

## Replay

`research/replay.py` es el skeleton read-only exigido por WP-02. Verifica:

- snapshot publicado e inmutable;
- experiment/candidate/artifact/decision lineage;
- configuración canónica;
- IDs de candidatos reproducidos;
- dependency lock hash;
- checksum de resultados;
- ausencia de autoridad productiva.

Dos ejecuciones sobre el mismo bundle producen el mismo
`replay_plan_checksum`. Un cambio de dependencia, snapshot, configuración o
lineage bloquea el replay.

## Pruebas cubiertas

- JSON/hashes independientes del orden y timestamps normalizados;
- IDs diferentes entre corridas, `attempt_id` persistido y run ID recomputable;
- identidad de artifacts/decisions idéntica entre runtime y replay;
- schema drift por tabla, columna, tipo, modo y columna inesperada;
- contratos PIT que no pueden falsificar disponibilidad;
- snapshots idénticos con identidad idéntica;
- quality gate fallido no publica;
- snapshot manipulado se rechaza, incluso si el checksum sustituto tiene forma SHA-256 válida;
- experimento incompleto no es publicable;
- candidato de otra corrida se rechaza;
- dependency drift bloquea replay;
- Strategy Brain crea `experiment_id` antes de `candidate_id`;
- candidatos permanecen `REGISTRY_PENDING` hasta commit completo;
- Dataform solo expone candidatos con lineage auditada;
- invariant assertion detecta colisiones, snapshots inválidos y autoridad productiva.
