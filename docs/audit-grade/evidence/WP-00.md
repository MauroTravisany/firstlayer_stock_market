## Estructura y readiness

- `validate_manifest_structure`: verifica schema, checksums, clasificación legacy, policy, seguridad y correspondencia de blockers; permite blockers correctamente declarados.

## BigQuery snapshot

Antes de consultar una fuente, `BigQueryReader` obtiene metadata con `get_table`:

- `TABLE` se normaliza a `BASE TABLE` y usa `FOR SYSTEM_TIME AS OF`;
- `VIEW` permite una lectura live explícita y registra `source_table`, `source_type`, `fallback_reason`, `exception_type` y `error_code`;
- cualquier otro tipo falla;
- permisos, autenticación, SQL, timeout, red y errores inesperados se propagan y fallan.

La captura final clasificó todas las fuentes consultadas como `BASE TABLE`, por lo que registra `SINGLE_SYSTEM_TIME_AS_OF` y ninguna fallback live. Cloud Scheduler, Cloud Run y Dataform se leen por APIs REST independientes; esas tres superficies no forman una transacción atómica y permanecen declaradas en `capture_atomicity.non_atomic_surfaces`.
