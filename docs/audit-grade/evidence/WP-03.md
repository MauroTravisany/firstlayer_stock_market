# WP-03 — Fundamentales y earnings point-in-time

Estado: **IMPLEMENTED_UNVERIFIED / PARTIAL** hasta completar CI final y validación BigQuery shadow.

Issue: #38

PR: #64

## Objetivo

Eliminar look-ahead de fundamentales y earnings. Ningún dato financiero puede ser consumido antes de una evidencia verificable de disponibilidad. `period_end_date` y `filing_date` no son sustitutos de `available_at`.

## Implementación de código

### Fuente financiera

- `cloud-functions/financial_data/custom_function/sec_source.py`
  - SEC EDGAR submissions + companyfacts.
  - exige `SEC_USER_AGENT` identificable;
  - usa `acceptanceDateTime` como `source_published_at`;
  - no inventa timestamps cuando SEC no los entrega;
  - obtiene año/trimestre desde metadata XBRL `fy/fp`;
  - discrimina valores trimestrales (~91 días) de acumulados YTD;
  - conserva accession, CIK, form y URL SEC;
  - obtiene shares/cash/debt para derivaciones históricas reproducibles.

### Identidad y revisiones

- `point_in_time.py`
  - `revision_id = SHA256(canonical immutable content)`;
  - `available_at = source_published_at` únicamente cuando existe evidencia;
  - filas sin disponibilidad verificable quedan `backtest_eligible=false`;
  - selección as-of requiere `available_at <= cutoff`.

- `financial_statements_pit_raw.sqlx`
  - tabla append-only;
  - una revisión jamás actualiza una revisión anterior.

- `pit_bq_operations.py`
  - inserta únicamente `revision_id` inexistentes;
  - no ejecuta `UPDATE` sobre revisiones previas.

### Consumidor PIT

- `financial_statements_pit.sqlx`: expone únicamente revisiones elegibles.
- `trading_financial_context_pit.sqlx`: join as-of contra timestamp UTC del signal.
- `financial_ttm_pit.sqlx`: reconstruye TTM para cada signal usando solo revisiones disponibles.
  - Q1/Q2/Q3 utilizan valores trimestrales;
  - un 10-K/FY no se trata como Q4 directo;
  - Q4 se deriva como FY − Q1 − Q2 − Q3 cuando todos los componentes existen;
  - si falta estructura, `ttm_complete=false`.

### Valoración shadow PIT

- `portfolio_valuation_pit_shadow.sqlx`
  - deriva market cap desde precio histórico × shares disponibles;
  - deriva P/E TTM, P/S TTM y P/B desde filings PIT;
  - no usa `financial_ratios_snapshot` de Yahoo;
  - no inventa `forward_pe` histórico;
  - `promotion_mode=SHADOW_ONLY`;
  - `production_change_allowed=false`.

### Earnings

- `earnings_events_pit.sqlx`
  - EXPECTED y REPORTED son eventos distintos;
  - `available_at=observed_at`;
  - un backfill histórico no mueve disponibilidad hacia atrás.

- `trading_earnings_context.sqlx`
  - solo consume eventos con `available_at <= signal_timestamp_utc`.

### Contexto y dual-run

- `trading_historical_context_pit.sqlx`
  - sustituye fundamentales/earnings/valoración legacy por fuentes PIT;
  - mantiene el carril shadow separado;
  - no reutiliza scores agregados legacy como evidencia PIT.

- `wp03_legacy_vs_pit_shadow.sqlx`
  - compara legacy contra PIT por fecha/signal/ticker;
  - clasifica divergencias;
  - `promotion_eligible=false`.

- `wp03_legacy_invalidation.sqlx`
  - declara explícitamente no promocionables las familias históricas afectadas;
  - exige recomputación sobre snapshot WP-03 PIT.

## Contratos

`contracts/financial_statements_pit_raw.yaml` formaliza el store SEC append-only. Está marcado `NOT_BACKTEST_ELIGIBLE` porque la tabla raw puede contener filas rechazadas; solo el filtro PIT puede alimentar investigación.

El contract manifest y runtime manifest deben regenerarse de forma determinista antes de considerar el PR listo.

## Pruebas añadidas

- filing tardío invisible antes de publicación;
- restatement preserva revisión anterior;
- YoY trimestral exacto;
- timestamp SEC ausente no se sintetiza;
- trimestre fiscal usa XBRL `fy/fp`;
- selección de fact duration quarter-vs-YTD;
- Q4 anual normalizado por FY − Q1-Q3;
- SQL contract prohíbe fallback por `period_end_date`;
- valoración PIT no puede usar ratio snapshot Yahoo;
- auditoría cubre financial current/prior, expected/reported earnings y valoración;
- resultados legacy afectados permanecen no promocionables.
